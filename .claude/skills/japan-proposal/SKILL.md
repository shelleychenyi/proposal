# 日本提案 skill

把一份 Pandora 聲量報告，變成一份可直接寄給日本客戶的提案簡報。

輸出對象是**日本企業**（多數透過經銷商 Intasect 交付），談的是**台灣市場**的口碑施策。
語言預設日文；使用者要繁中版時改用 `template_zh`。

## 工作流程

### 1. 讀懂 Pandora 報告 → 抽出事實

先看 `references/pandora-report.md`（報告有哪幾頁、哪些數字在哪裡、哪些欄位可能不存在）。

Pandora 報告多半是**整頁截圖**。用 Read 工具逐頁看圖，把數字抄下來，**不要憑印象填**：

```bash
python3 scripts/extract_report.py <pandora報告.pptx|.pdf> -o /tmp/<案子>/pandora
```

會把每頁圖片抽出來，並印出建議的裁切區塊。抽完**一定要用 Read 看過每一張**，把數字讀出來。

必抄的數字：總聲量、總文章數、總按讚數、總留言數、平均按讚／留言、平台分布％、
聲量高峰月與數值、聲量空白月與數值、看板排行、Top10 熱門文章的主題傾向。

### 2. 決定策略（這一步不能跳）

看 `references/strategy-playbook.md`。核心是四個判斷：

1. **空白在哪**——高峰月 vs 空白月、平台偏向、掲示板比率。空白＝先行佈局的機會。
2. **誰在談**——從 Top10 貼文反推受眾分群（通常 3 群，不要硬湊 4 群）。
3. **怎麼動**——旅マエ／旅ナカ／旅アト 各階段要做什麼。
4. **切角**——從 Top10 實際被討論的主題長出 5 個投稿切角，**不要自己發明客戶沒有的賣點**。

每一個策略主張，都要能指回 Pandora 的哪一頁哪個數字。範本的「根拠」欄就是為此而存在。

### 3. 寫 brief.json

`references/anchor-map.md` 是範本每一個欄位的錨點對照表（323 個）。
`references/example-brief.json` 是一份完整的實例（長島度假村），照著改最快。

隨時可以重新確認錨點：

```bash
python3 scripts/inspect_template.py ja --page 4
```

寫作規範看 `references/japanese-style.md`——敬語、標題命名、出典寫法、保證與參考值的措辭。

### 4. 有預算就做 KPI 預測

看 `references/pricing-kpi.md`。裡面是實際成交過的單價與 KPI 換算公式。

**KPI 必須分三類標示，不可混寫**：

| 類別 | 意義 | 例 |
|---|---|---|
| 保証 | 未達成有退費／補件條款 | 声量＋30%、AI検索12KW掲載、KOC単篇Views 10,000 |
| 目標値 | 依實績設定的努力目標，非合約值 | フォロワー数、平均エンゲージメント率 |
| 承諾交付 | 一定會交付的量 | 投稿本数、レポート、KW設計組数 |

沒有預算就不要編 KPI 數字；改寫「予算規模が決まり次第、KPIを設計します」。

### 5. 產出與檢查

```bash
python3 scripts/build_deck.py /tmp/<案子>/brief.json
```

腳本會回報套用了幾項、有沒有打錯的錨點、有沒有殘留的【】。接著**一定要目視檢查**：

```bash
python3 scripts/render.py <輸出.pptx> -o /tmp/<案子>/shots
```

用 Read 逐頁看圖，重點檢查：文字溢出卡片、截圖被壓扁、標籤壓到長條、空白區塊沒清掉。
發現問題改 brief.json 重跑，不要手動改 pptx。

## 版面規則（照做就不會出錯）

- **只換內容，不動版型。** 位置、字級、顏色全部沿用範本。要改版面就改 `scripts/build_template.py` 重生範本。
- **不用的區塊要整區移除**，不要留空卡片。用 `hideRegion`（見 build_deck.py 說明）。
  - 單一品牌（沒有第二組關鍵字）→ 移除 p3 右卡 `[6.70, 2.10, 6.10, 4.60]` 與 p10 第二組 `[0.80, 3.60, 7.00, 0.85]`
  - 只設 3 個 TA → 移除 p6 第四張卡 `[9.75, 1.65, 3.00, 3.80]`
- **短欄位有字數上限**：p4 的五個列標籤 ≤6 全形字；卡片標題 ≤12 全形字；chip ≤10 全形字。超過會換行壓到旁邊元素。
- **Pandora 截圖用 `images` 貼**，會等比縮放置中並自動移除虛線佔位框。先裁切成只有圖表本身，不要把整頁塞進去。
- **p4 可以改用途**。Pandora 報告若沒有情緒五級與關鍵字地圖（多數沒有），就把 p4 改成
  「看板別ランキング × 人気投稿テーマ」——所有標籤都是可改的錨點，example-brief.json 就是這樣做的。

## 絕對不要做的事

- 不要編造 Pandora 沒有的數字。報告沒有的欄位就換一個有資料的角度講。
- 不要把「目標値」寫成「保証」。日本客戶會照字面理解，這是合約風險。
- 不要在提案裡承諾業配不標示。台灣公平交易委員會規範，KOC 貼文一律標「合作」，
  這一點要主動寫進提案（範本 p9 註記已有，不要刪）。
- 不要用中文語序直翻日文。看 `japanese-style.md`。

## 檔案

| 路徑 | 內容 |
|---|---|
| `assets/template_ja.pptx` / `template_zh.pptx` | 提案範本（11 頁，323 個錨點） |

| `scripts/build_template.py` | 重新產生範本（改版面時才動） |
| `references/` | 方法論、日文規範、價目與 KPI、錨點表、完整實例 |
