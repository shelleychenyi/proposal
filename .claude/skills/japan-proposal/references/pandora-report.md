# 怎麼讀 Pandora 聲量報告

Pandora（by The Pocket Company／Accucrazy）是台灣社群聆聽工具。
客戶端交付的報告通常是 **6 頁整頁截圖的 pptx 或 pdf**——文字都在圖片裡，
`python-pptx` 抽不到任何文字。**必須用 Read 工具看圖判讀。**

## 標準 6 頁的內容

| 頁 | 標題 | 可抽出的事實 |
|---|---|---|
| p1 | 封面 | 品牌名、**資料範圍**（例：2025/5/28 ~ 2026/5/27）→ 出典行要照抄 |
| p2 | 基本統計 | 總文章數／總按讚數／總留言數／平均按讚數／平均留言數／**總聲量** |
| p3 | 平台與看板分布分析 | 左：平台分布圓餅（threads／instagram／ptt／dcard ％）<br>右：聲量看板排行（各看板文章數與互動數） |
| p4 | 聲量趨勢分析 – 聲量趨勢 | 月度折線。**讀出高峰月的月份與數值、空白月的月份與數值** |
| p5 | 聲量趨勢分析 – 文章數 | 月度長條。看發文密度與聲量是否脫節 |
| p6 | 文章列表 – 精選熱門文章 Top 10 | 分「超高討論／反應熱烈／略有回應」三層，各含標題、來源、看板、讚、留言 |

也可能拿到 **洞察報告**（20 頁以上），內容更深但同樣是截圖；讀法一樣。

## 聲量的定義（提案裡要寫對）

```
声量（Volume）= 10 + いいね数 × 3 + コメント数 × 5
```

所以總聲量遠大於文章數是正常的。出典註記要寫成：

> ※ 総声量は、いいね・コメント等の反応を加重集計したPandora独自指標です（10＋いいね×3＋コメント×5）。

## 判讀時最容易出錯的四件事

1. **「總聲量高」不等於「口碑好」。**
   長島度假村總聲量 261,739，但文章數只有 134 本，且 7 成集中在單一月份。
   正確結論是「有素材、缺設計」，不是「已經很好了」。

2. **高峰月要找出成因。** 對照 p6 的 Top10，看那個月被討論的是什麼題材。
   寫不出成因就不要斷言，改寫「要因は【要確認】」。

3. **空白月是提案的核心武器。** 空白月＝競合不在場＝先行佈局的時機。
   長島案的整個策略就是「12月181,231件 vs 9月259件 → 秋に佈局、冬に刈り取る」。

4. **報告沒有的欄位不要編。**
   標準 6 頁報告**沒有**情緒五級分布、沒有關鍵字地圖、沒有競品比較。
   Pandora API 有 `sentiment` 欄位，但截圖報告通常不含。
   → 沒有就把範本 p4 改成「看板別ランキング × 人気投稿テーマ」（見 example-brief.json）。

## 從 Top10 熱門文章長出切角

這是整份提案最有價值的一步。做法：

1. 把 10 則標題抄下來，看反覆出現的**名詞**與**情境**。
2. 歸成 3 群左右，每群給一個文脈名稱。
   長島案：①絕叫挑戰（鋼鉄龍2000・白鯨・ギネス記録）②親子旅行（3日2泊・mini vlog）
   ③冬季複合體驗（イルミ×温泉×アウトレット）。
3. 這 3 群直接對應 p4 的三個文脈欄、p6 的受眾分群、p8 的投稿切角。

**切角必須從實際被討論的內容長出來**，不是從客戶的官方賣點長出來。
客戶想講的和消費者在講的不一樣時，提案要以消費者為準，再把客戶的賣點嫁接進去。

## 有 API 可用時

如果手上有 Pandora API key，`提案skill/pandora/` 有一套已跑通的工具
（`cli.py check / fetch / build`），可以直接抓原始貼文算出精確指標，
包含截圖報告沒有的情緒分布與平台占比。文件見該資料夾的 README.md。
API 只有 `posts` / `trends` scope 時抓不到即時爬取資料。
